# 合租生活管家设计规格

## 目标

为 2–5 人合租室友提供一个打开即用的生活工作台，帮助他们在同一处查看并维护本月费用、清洁值日、公共物品库存和室友公约，减少分摊不清与遗忘。

## 用户与成功标准

- 主要用户：需要共同维护房屋事务的合租室友。
- 评审成功标准：公开链接可直接访问；首次打开能理解当前房屋状态；费用、值日、物品、公约四项能力都有可操作的新增/编辑路径；刷新后数据仍保留。
- 约束：无需登录和后端服务即可完成演示；示例数据必须明确标为示例房屋；部署地址保持不变。

## 信息架构

单页工作台，左侧导航切换五个视图：

1. 总览：本月总支出、个人应付/已付、今日值日、低库存物品、最近动态。
2. 费用：费用条目列表、付款人、参与人、金额和 AA 计算；支持新增、删除、标记已结清。
3. 值日：按周展示公共区域任务与负责人；支持新增任务、切换完成状态、调整负责人。
4. 物品：公共物品库存、单位、最低库存和补充状态；支持新增、修改数量、标记已购买。
5. 公约：可确认的规则清单；支持新增规则、切换确认状态、删除规则。

顶部提供房屋名称、成员数量、当前月份和“重置示例数据”入口。移动端导航折叠为顶部横向标签。

## 视觉方向

采用 Swiss 视觉锚点：白色/浅灰表面、Helvetica/系统无衬线字体、珊瑚红强调色、1px 网格线、左对齐和紧凑数字排版。差异化动作是将“房屋状态”作为一条连续的纵向状态轨：费用、值日、库存和公约的下一件待办沿同一条红色基准线排列，首屏就能看出需要处理的事情。

## 数据与行为

前端使用 React + TypeScript + Vite。应用状态由一个房屋状态对象组成，序列化到 `localStorage`；所有写操作都通过状态更新函数完成并立即持久化。金额使用分为“元”的整数分值避免浮点误差，展示时格式化为人民币金额。示例数据在本地没有状态时写入，并在界面上显示“示例房屋”标记。

## 组件边界

- `AppShell`：导航、房屋头部和视图切换。
- `OverviewView`：聚合统计与待办状态轨。
- `ExpensesView`：费用表单、列表、结算摘要。
- `ChoresView`：值日任务表格和完成状态。
- `SuppliesView`：库存卡片和补货操作。
- `HouseRulesView`：公约列表和确认操作。
- `useHousehold`：状态初始化、更新、重置和本地持久化。

## 验证

- `npm run build` 必须成功。
- 浏览器验证首次打开、四个模块的新增/切换操作、刷新后数据保持、移动端不出现横向溢出。
- 部署后从公开链接冷启动访问，确认不需要权限或本地开发服务器。

## 部署

生成静态 `dist` 目录，使用一个公开、长期可访问的静态托管地址；后续仅更新该地址的部署内容，不更换域名。
